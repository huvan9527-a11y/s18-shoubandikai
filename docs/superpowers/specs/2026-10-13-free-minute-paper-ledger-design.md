# 免费分钟行情模拟仓闭环设计

## 目标

把现有 S18 模拟撮合、可公开获取的分钟行情、持久化账户与可查看报告接成一个收盘后运行的模拟仓流程；让超出实时窗口的开盘提醒安全跳过，不把延迟运行误当作实时信号。

## 已确认的约束

- 资金固定 200,000 元、最多两个持仓槽，继续使用仓库现有 OPP3 撮合规则。
- 仅模拟，不发送券商订单。
- 分钟行情使用 AkShare 的东财 A 股 1 分钟接口，数据取自最近交易日。
- 该公开接口只保证近期分钟数据（文档标明 1 分钟为近 5 个交易日），且较早交易日可能没有有效分钟开盘字段。因此每个纸面交易日只接受当日完整、时间戳正确、OHLC 与流动性字段有效的分钟数据；不得用缺失字段补齐、盘后开盘价复盘报告或日线价格推定成交。
- 第一次成功的模拟运行以首个完整且新鲜的分钟交易日作为账本起点；不虚构 2026-10-08 起的历史成交。延迟/缺失的交易日保持未处理并在账户报告中明确显示，不能声称追平。
- GitHub Actions 定时任务可能延迟。09:25–09:35 之后不发实时开盘提醒；保留非实时诊断用途，并以成功跳过表示错过窗口。

## 流程

1. 现有盘后扫描生成当日完整信号报告，并复用其当日候选。
2. 账户执行器只处理经过完整性验证的当日分钟数据。复用 `src.paper.replay_day` 的原撮合逻辑和时段、费用、T+1 与涨跌停限制；逐分钟成交量由“手”换算成股后交给撮合器。
3. 撮合完成后原子保存账户，并更新 `outputs/latest.json`、`outputs/latest.md`、`outputs/holdings.csv`、`logs/trades.csv`、`logs/equity.csv`。GitHub Actions 总结页也显示最新账户摘要和交易状态。
4. 缺行情、数据日期不符、分钟缺口、无效 OHLC 或成交量单位校验失败时，账户账本保持原样，工作流失败并留出诊断。可在当日第二个收盘时段重试。
5. 开盘提醒在有效时间窗外作为安全跳过；不得发送过期的买入候选或把复盘结果标为成交。

## 验收标准

- 对有效当日分钟数据，已有撮合规则能记入买卖、费用、持仓和权益；同一交易日重复运行不产生重复交易。
- 对旧交易日、过时行情、缺失关键分钟、错误 OHLC、空/不完整数据或单位错误，账户不变且报告可识别原因。
- 空仓是有效模拟结果，报告明确初始资金、现金、权益、累计成交数和已处理日期。
- 两个工作流分别能表示有效的收盘模拟账本运行与错过实时窗口后的安全跳过。
- README 指向唯一的最新模拟仓报告，并说明免费行情的覆盖限制、未成交与缺数语义。
