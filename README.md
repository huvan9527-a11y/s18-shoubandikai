# S18 OPP3 · 20万元 GitHub Actions 模拟仓

使用此前认可的 `S18_OPP3_execution(1).py`（OPP3 v2.0 执行加固版）规则。
初始资金 **200,000 元**，独立账本，最多持有两只。默认单槽资金上限为账户权益的50%，实际金额还受成交额、现金、股数和手续费约束。

## 当前运行方式：日线扫描与模拟仓撮合

不依赖聚宽，不需要 `JQ_USERNAME` / `JQ_PASSWORD`。开盘后使用免费1分钟行情先记入当日买入；收盘扫描再完成估值与T+1退出，不会重复买入。

- 股票日线、成交额、成交量与复权因子：新浪公开行情；指数日线：腾讯。
- 中证1000成分：中证指数官方文件；备用数据必须去重后恰好1000只，否则报错。
- 根据信号日前一交易日的历史日线计算市场条件与候选，再按当日开盘价筛选信号。
- 工作日北京时间16:23、18:23扫描最近两个已完成交易日，并在扫描成功后撮合最近交易日。两次运行对同一交易日幂等。手动扫描可输入日期，例如 `2026-10-08 2026-10-09`。
- 开盘工作流提前启动并等待09:31—09:36分钟线完整；北京时间09:37—10:00可补记当日早盘模拟买入。收盘工作流只处理T+1卖出、收盘估值及日账，不会重复早盘买入。Actions超时/排队超过10:00或分钟数据不完整时明确跳过/报错，不伪造成交；盘后回放仍可按完整分钟行情处理当天。
- 扫描输出在 `outputs/signals-YYYY-MM-DD.json` / `.md`。状态 `scanned` 表示日线与开盘条件扫描完成；模拟仓状态见 `outputs/latest.md`。
- 空信号为正常结果，退出码为0；只有实际日线、股票池、日期等数据错误才返回非零。
- 每50只股票输出一次采集进度。缺失股票池或行情不能解释成零信号。

当前公共接口的历史逐日成分及历史ST状态不能完整还原，因此报告保留成分快照口径说明。

### 模拟仓与查看位置

- 人读入口：[`outputs/latest.md`](outputs/latest.md)。GitHub 仓库页面打开该文件即可；Actions 运行摘要也附有该报告。
- 账户状态：[`outputs/latest.json`](outputs/latest.json)；持仓：[`outputs/holdings.csv`](outputs/holdings.csv)；模拟成交：[`logs/trades.csv`](logs/trades.csv)；每日净值：[`logs/equity.csv`](logs/equity.csv)。Actions 运行页 artifact `s18-paper-reports-*` 保存这些文件。
- 使用 AkShare/Eastmoney 免费1分钟不复权行情，接口约保留最近5个交易日。早盘只要求09:30—09:36完整分钟窗，日终回放另要求14:50—14:57退出窗；成交量从“手”换算为股。缺分钟、过期日、零开盘价或 OHLC 错误会拒绝当次撮合，不使用日线或合成数据补成交。
- 首次成功撮合日成为账本起始日，不回填此前历史。已有账本漏过交易日时生成 `outputs/paper-status.json` 诊断并保持账户不变；同日重跑不会重复成交。
- 初始资金固定20万元、最多两只持仓。所有成交是 `src/paper.py` 的假设撮合，不是券商订单或成交回报。

## 保留的 S18 规则

原策略目标股票池：昨日中证1000成分（公共数据版本的历史口径限制见上文）（`000852.XSHG`），剔除ST/退市、上市不足250自然日、61日历史不完整/停牌股票；昨日成交额至少1亿元。

| 优先级 | 组件 | 个股条件 | 开盘及买入时低开区间 | 市场条件 |
|---|---|---|---|---|
| 1 | FB_dip | 昨日首板、前日价格低于之前60日收盘中位数、非一字首板、10%板 | −7%～−2% | 指数低于MA20且跌停比例<3% |
| 2 | LB | 昨日连续涨停≥2天 | −4%～−2% | 跌停比例<3% |
| 3 | DEEP | 昨日既非涨停也非跌停 | −9%～−3% | 冰点且连续冰点≥2天或指数偏离MA20≤−4% |

冰点：昨日涨停股当日平均溢价≤−1%，或跌停比例≥1%；预热40个交易日，历史成分口径限制见上文。

- 买入窗口 **9:31—9:35**，同组件按低开更深、股票代码排序；当天最多选中两只，每只最多两次买单，部分成交后不补仓。
- 价格≤190元；当前价仍在低开区间；追价不超过开盘+0.3%；排除距跌停≤0.5%、涨停和疑似除权日。
- 单笔金额不超过昨日成交额0.1%、上一完整分钟成交额10%；预留1%现金。
- 买入后 **下一交易日14:50—14:56** 退出，未卖出持仓以后交易日继续退出；T+1、停牌和跌停限制保留。
- 没有额外增加5%/6%止损或改为三天持仓；以该执行版为准。

## 模拟账本文件

`state/account.json` 是权威账本；导出的账户摘要、持仓、成交和净值位于上方列出的 `outputs/` 与 `logs/` 文件。分钟来源不可回补历史，因此账本只验证并处理最新的完整交易日。

## Server 酱推送

在仓库 Actions Secrets 中添加 `SERVERCHAN_SENDKEY`（也兼容 `SERVERCHAN_KEY`、`SERVER_CHAN_SENDKEY`、`SCKEY`）。支持 SCT 开头的 Server 酱 Turbo Key 和 sctp 开头的 Server 酱 3 Key；不要把密钥写入源码。

当前16:23、18:23工作流在扫描结束后推送本次扫描报告，包含候选代码、名称、组件、低开幅度和运行链接；零候选和数据失败也明确提示。消息为收盘后历史扫描，不是实时买卖指令，不代表成交。未配置密钥时跳过推送。

相同日期、相同报告只发送一次，报告变化后重新发送。仅服务返回成功后才记录到 `state/notifications.json`，工作流保存该状态；失败返回非零并保留重试机会。服务接受发送不等于手机已收到。网络超时存在已发送但未确认的可能，下一次运行可能重复发送。

## 双仓对照计划（2026-10-12 增补）

新增 `src/dual_plan.py`，根据已经完成的 `outputs/signals-YYYY-MM-DD.json` 输出独立的双仓计划 `outputs/dual-plan-YYYY-MM-DD.json`。

- A仓：T日09:31—09:35买入、T+1日14:50—14:56卖出；必须有当时的分钟行情及成交依据，过时不补买。
- B仓：T日信号股票在T+1日开盘尝试买入，无需T+1日再次满足低开幅度；T+2日14:50—14:56卖出。停牌、涨跌停、流动性和交易规则仍适用。
- 两仓各自以20万元为初始资金基准，不共用持仓与收益。计划中的 `shares=0`、`execution_confirmed=false` 代表**尚未模拟成交**，不能当作已买入。
- 运行示例：`python -m src.dual_plan --signal-date 2026-10-12 --next-trading-day 2026-10-13 --second-trading-day 2026-10-14`。
- **尚未接入 Actions 自动触发、真实开盘/分钟撮合、双账户持久化或 Server酱成交推送。** 当前定时工作流仍然是盘后扫描；不可宣称已完成自动模拟仓部署。

## 09:26 开盘竞价提醒

独立工作流 `.github/workflows/s18-opening-alert.yml` 在工作日北京时间08:45启动，安装行情依赖后等待09:25，在09:25—09:35窗口内读取主分支前一日已保存的 `next_session.candidates`，采集并校验腾讯竞价行情，再向Server酱发送候选提醒。推送仅表示经过竞价数据校验的候选，不代表模拟成交或券商订单。

- 依赖安装或GitHub排队若延迟到09:35之后，任务会安全跳过，不发送过时提醒、不补成交。GitHub cron不能保证准点启动，具体启动时间请看Actions日志。
- 运行需要配置Actions Secret：`SERVERCHAN_SENDKEY`（也兼容 `SERVERCHAN_KEY`、`SERVER_CHAN_SENDKEY`、`SCKEY`）。未配置时推送步骤会失败，不会静默报告已提醒。
- `state/opening_notifications.json`保存当日去重状态，由工作流提交回主分支。
- 每日盘后扫描继续在北京时间16:23、18:23运行；其09:36后复盘只作诊断，不会冒充实时提醒。
- 09:25竞价提醒只读前一交易日已生成的候选。因此盘后扫描必须先成功并把报告保存到主分支；缺少新鲜报告时拒绝发送。
